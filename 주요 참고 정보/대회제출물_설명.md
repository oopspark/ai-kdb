- 서버는 공인 IP를 부여받아 외부에서 접근 가능해야 하며, 네트워크(VPC, Subnet), 서버 생성, 방화벽 설정, 인증서(HTTPS) 설정 등이 필요합니다.
- 서버 사양은 2CPU, 4GB 메모리, 20GB 저장소를 권장합니다.

- 실제 서비스는 클로바 스튜디오가 아닌 하이퍼클로바X API와 직접 통신해야 하며, API Key를 발급받아야 합니다.

### Ontology(온톨로지)와 Knowledge Graph(지식 그래프)
- Ontology는 개념과 규칙(예: ETF는 운용사가 있고, 위험등급이 있다 등)을 정의하는 설계도 역할을 하며, Knowledge Graph는 실제 데이터를 온톨로지 구조에 맞게 연결한 인스턴스 데이터입니다.
- 온톨로지는 용어 표준화, 지능형 추론, 데이터 무결성, AI 신뢰성 확보에 중요합니다.
- 온톨로지는 RDF, Turtle 등 포맷으로 작성하며, 규칙 위반(예: 위험등급 99등급 등)은 저장 전 검증해야 합니다.
- 온톨로지를 활용하면 LLM이 역추론, 관계 추론 등 다양한 질의에 근거 있는 답변을 할 수 있습니다.

### Knowledge Graph 구축 및 활용
- Knowledge Graph는 엔티티(객체), 관계, 속성으로 구성된 네트워크형 데이터 구조입니다.
- 자연어 문서를 트리플(주어-서술어-목적어)로 분해해 그래프를 만듭니다.
- 기존 RAG 방식의 한계(문서 chunk별 정보 단절 등)를 극복하기 위해, 그래프 탐색, 키워드 매칭, 벡터 검색, SQL 등 다양한 검색 방식을 융합(Federated Query)해 활용합니다.

### 과제 안내 및 평가 기준
- 참가자는 금융상품(국내주식, ETF, 공모펀드 등) 관련 데이터를 활용해 에이전트(Agent)를 개발해야 하며, 하이퍼클로바X를 통한 답변 생성이 필수입니다.
- 데이터는 주최 측 제공 데이터가 기준이며, 외부 데이터 활용은 가능하나 기준일(7월 11일) 이후 데이터는 인정되지 않습니다.
- 답변에는 반드시 근거(출처)를 명시해야 하며, 데이터로 확인 불가한 질의에는 "확인할 수 없음"을 명확히 밝혀야 합니다.
- 답변 불가 질의에 답변 시 감점, 응답 속도(15초 이내 권장), 소스코드/기술제안서/ontology 파일 제출 등 세부 규정이 있습니다.
- 평가 항목은 소스코드(20%), 기술제안서(40%), API 답변(40%)이며, 답변의 정확성, 근거 제시, 응답 속도 등이 중요합니다.

### 기타 Q&A
- 멀티턴(다중질문) 지원은 필수가 아니며, 단일 질문-단일 답변 구조를 권장합니다.
- UI는 예선 평가에 포함되지 않으며, 본선에서 라이브 데모가 있을 수 있습니다.
- 답변의 정답은 엔티티와 관계가 모두 포함되어 있는지, 근거가 명확한지로 평가합니다.
- 외부 데이터 활용 시 기준일 이전 데이터만 인정되며, 최신 데이터 반영은 감점 요인입니다.

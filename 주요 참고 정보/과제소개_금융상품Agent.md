# 2. 과제 개요

## 2.1 목표

국내채권, 국내 ETF, 해외 ETF, 공모펀드 데이터를 기반으로 사용자의 자연어 질의에 맞는 상품 정보를 **조회·비교·설명하는 금융상품 AI Agent**를 개발합니다.

단순한 키워드 검색을 넘어, Agent가 대규모 정형 상품 데이터를 스스로 탐색하고 연산하며, 데이터 근거에 기반해 답변하는 **Agent RAG 및 QA 구현**이 핵심입니다.

## 2.2 핵심 구현 과제

### 1) 데이터 구조화 설계

- 채권, ETF, 펀드 등 상품군마다 스키마가 다른 **4종 마스터 데이터**의 특성을 분석
- 참가팀이 판단한 최적의 방식으로 데이터를 구조화
- 구조화된 데이터를 Agent와 연동하도록 설계

### 2) 검색 및 Agent 오케스트레이션

- 질의 유형과 조건에 맞는 상품 검색
- 조건 필터링
- 정렬, 순위, 집계 등 필요한 연산 수행
- 위 기능을 Agent 파이프라인으로 연동
- 신뢰도 높은 답변 생성

### 3) 질의 유형 및 의도 이해

자연어 질의에 포함된 다음 요소를 복합적으로 파악해야 합니다.

- 상품 유형
- 자산군
- 투자 지역
- 위험 등급
- 보수
- 수익률
- 그 밖의 상품 조건

Agent는 파악한 의도와 조건에 맞춰 적절한 상품 정보와 근거를 제공해야 합니다.

# 3. AI Agent의 역할

## 3.1 상품 검색 및 조회

### 조건 기반 상품 검색

사용자가 제시한 조건에 부합하는 상품을 검색합니다.

- 자산군
- 투자 지역
- 위험 등급
- 보수
- 수익률
- 기타 상품별 조건

### 상품 정보 조회

검색한 상품의 세부 정보를 조회합니다.

- 기초지수
- 운용사
- 보수
- 만기
- 신용등급
- 수익률
- 기타 제공 데이터에 포함된 상품 속성

## 3.2 비교 및 연산

### 상품 간 비교 분석

동일하거나 유사한 유형의 상품을 다음 기준 등으로 비교합니다.

- 보수
- 수익률
- 상품 규모
- 순자산 또는 AUM
- 기초지수
- 그 밖의 비교 가능한 상품 속성

### 계산 기반 질의

다음과 같이 연산이 필요한 질의를 처리합니다.

- 정렬
- 순위
- 집계
- 조건별 필터링
- 수치 비교

### 상품군 교차 질의

국내채권, 국내 ETF, 해외 ETF, 공모펀드 등 서로 다른 상품군을 넘나드는 질의를 처리합니다.

## 3.3 근거 기반 답변

### 상품 정보 설명

- 제공 데이터에 담긴 상품 정보를 사용자가 이해하기 쉽게 설명
- 답변과 함께 참조한 데이터 또는 근거를 제시

### 환각 방지

- 데이터에 없는 내용을 추측하지 않음
- 확인할 수 없는 내용을 사실처럼 생성하지 않음

### 조건부 안내와 역질문

- 질의의 정보가 부족하면 확인이 필요한 조건을 사용자에게 역질문
- 단정적인 투자 추천은 지양

## 3.4 답변 형태 예시

자료의 예시 그래픽에서는 다음과 같은 답변 구성을 제시합니다.

1. 결론: 조건에 부합하는 상품 3종
2. 비교·연산: 상품별 총보수, 순자산(AUM), 기초지수 비교
3. 근거: 참조 테이블과 데이터 기준일

> 위 구성은 단순 예시 그래픽이며 평가 기준과 직접적인 관련은 없습니다.

# 5. 구현 범위

구현 범위와 방식에는 제한이 없습니다. 참가팀은 데이터 적재, 전처리, 구조화, 색인, 검색 방식을 자유롭게 선택할 수 있습니다.

활용 가능한 방식의 예시는 다음과 같습니다.

- RDB
- GraphDB
- Text-to-SQL
- Vector DB
- RAG
- Re-ranker
- Agent Framework
- 이외 참가팀이 적절하다고 판단한 기술

# 6. 데이터 활용 규칙

평가에 직접 연결되는 제약이므로 반드시 준수해야 합니다.

## 6.1 데이터 수집 및 활용 범위

| 구분 | 규칙 |
|---|---|
| 가능 | 금융상품과 관련한 데이터는 참가팀이 별도로 수집해 활용 가능. 비정형 데이터도 포함 가능 |
| 기준 | 주최 측이 제공한 데이터가 평가 시 사용하는 기준 데이터 |
| 우선 | 외부 수집 데이터와 주최 측 데이터가 서로 충돌하면 주최 측 제공 데이터가 우선 |

## 6.2 답변 생성 원칙

| 구분 | 규칙 |
|---|---|
| 필수 | 답변은 데이터를 근거로 생성하고, 근거가 된 참조 데이터를 표시 |
| 필수 | 데이터로 확인할 수 없는 질의는 **확인할 수 없음**이라고 명시하거나, 답변에 필요한 조건을 역질문 |
| 금지 | 데이터 근거가 없는 수익률 전망 생성 |
| 금지 | 단정적인 투자 추천 생성 |

## 6.3 예시 질문

- 참고용 예시 질문 세트는 본 소개자료에 포함되어 있지 않습니다.
- 오프라인 설명회에서 공지될 예정입니다.

# 7. 평가 방법

## 7.1 예선

정량평가와 정성평가를 혼합한 종합평가를 통해 최종 본선 진출팀을 선발합니다.

### 정량평가

- 참가팀이 준비한 **평가용 API Endpoint**에 주최 측 평가 담당자가 `GET` 요청 수행
- 비공개 평가문제에 대한 참가팀의 답변을 호출하여 평가
- 평가문제는 난이도 **상·중·하**를 혼합하여 구성

### 정성평가

각 주제별 기술 전문가와 도메인 전문가의 검토를 바탕으로 진행합니다.

검토 항목:

- 문제 정의
- 기술 완성도 및 성능
- 창의성 및 확장성
- 답변의 정확성 및 일관성
- 현업 활용성 및 리스크 관리

## 7.2 결선

- 최종 본선 진출 **6팀**을 대상으로 결선 심사 및 평가 진행
- 제안 기술에 관한 **PT 및 라이브 시연 발표** 중심으로 평가
- 평가위원의 현장 종합평가로 진행 예정
- 세부 내용은 추후 공지

- 주최 측이 요청을 보내고 응답을 받을 수 있는 서버 개설
- 서버 환경:
  - 제공 Credit을 활용한 네이버클라우드(NCP)
  - 또는 참가팀이 선호하는 환경
- 필수 네트워크 조건:
  - **Public 망 통신이 가능한 네트워크**
- 예선 평가 기간 중 지정된 기간에는 API를 반드시 활성화 상태로 유지

### API 활성화 유지 예정 기간

- **09.07 - 09.20**
- 변경 시 별도 공지 예정

> 네이버클라우드플랫폼 자원을 사용할 경우 Credit 한도를 초과하지 않도록 주의해야 합니다. 초과 사용분에 대해 주최 측이 별도로 비용을 보전하지 않습니다.

## 9.2 요청 방식

- HTTP 메서드: `GET`
- Endpoint 예시: `https://{team-endpoint}/answer`
- Query parameters:
  - `question_id`: 평가 질문 식별자
  - `question`: 평가 질의 원문

## 9.3 cURL 요청 예시

```bash
curl -G "https://{team-endpoint}/answer" \
  --data-urlencode "question_id={id}" \
  --data-urlencode "question={평가 질의}"
```

## 9.4 Python 요청 예시

```python
import requests

resp = requests.get(
    "https://{team-endpoint}/answer",
    params={
        "question_id": "Q-001",
        "question": "평가 질의",
    },
)

result = resp.json()
```

## 9.5 응답 JSON 예시

참가팀 API가 주최 측에 반환하는 응답 예시입니다.

```json
{
  "question_id": "Q-001",
  "question": "평가 질의 원문",
  "retrieved_context": "답변 생성에 참고한 검색 문서",
  "think_trace": "사고·추론·도구 사용 과정",
  "answer": "최종 생성 답변"
}
```

### 응답 필드

| 필드 | 의미 |
|---|---|
| `question_id` | 요청받은 평가 질문의 식별자 |
| `question` | 평가 질의 원문 |
| `retrieved_context` | 답변 생성에 참고한 검색 문서 또는 검색 결과 |
| `think_trace` | 사고, 추론, 도구 사용 과정 |
| `answer` | 최종 생성 답변 |

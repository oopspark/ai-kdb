## 한눈에 보는 핵심 요약

이번 설명회는 AI 페스티벌의 **금융상품 검색·추천 에이전트 개발 과제**를 안내하는 자리였습니다. 참가팀은 제공 데이터와 외부 금융 데이터를 활용해 온톨로지·지식 그래프 기반 검색 시스템을 만들고, **HyperCLOVA X로 근거 있는 최종 답변을 생성하는 API**를 제출해야 합니다.

### 1. 과제의 핵심

- 사용자의 금융상품 질의를 분석하고 적합한 상품 정보를 검색해 답변하는 에이전트 개발
- 단순 벡터 검색보다 다음을 결합한 검색 구조가 권장됨
  - 관계 검색: 지식 그래프
  - 의미 검색: 벡터 DB
  - 조건·수치 검색: RDB/SQL
  - 키워드 검색
- 최종 답변에는 반드시 **근거가 표시**되어야 함
- 데이터로 확인할 수 없는 내용은 추측하지 말고 **“확인할 수 없음”**이라고 답해야 함
- 근거 없는 수익률 전망이나 “무조건 좋은 상품” 같은 표현은 감점 대상

### 2. 권장 시스템 흐름

`사용자 질의 → 의도·개체 분석 → 온톨로지 기반 의미 정규화 → 검색 경로 결정 → 여러 데이터 소스 검색 → 결과 검증 → HyperCLOVA X 답변 생성 → 근거 제시`

특히 답변 생성 직전에 실제 보유 데이터에 존재하는 정보인지 다시 검사하는 **검증 단계**가 중요합니다. LLM이 외부 지식으로 그럴듯한 답을 만들어내더라도 기준 데이터에 없으면 답변해서는 안 됩니다.

### 3. 온톨로지와 지식 그래프

- **온톨로지**: 금융상품의 개념, 속성, 관계, 제약조건을 정의한 설계도
- **지식 그래프**: 온톨로지에 실제 데이터를 연결한 결과
- **Retrieval**: 만들어진 데이터를 질의에 맞게 조회하는 검색 엔진

주요 활용 목적은 다음과 같습니다.

- ‘운용사’, ‘AMC’처럼 서로 다른 용어의 표준화
- 상품과 운용사 등 관계를 이용한 정방향·역방향 추론
- 위험등급처럼 허용 범위를 벗어난 잘못된 데이터 차단
- 답변이 어떤 데이터와 관계를 통해 생성됐는지 추적
- 여러 관계를 거쳐야 하는 복합질의 처리

온톨로지 표현 형식은 자유지만 Turtle(`.ttl`) 형식이 권장됩니다. `.ttl` 파일 자체가 의무인 것은 아니며, **도메인별 온톨로지를 제출하는 것이 핵심**입니다.

### 4. 데이터 사용 기준

- 제공 데이터의 기준일: **2026년 7월 11일**
- 제공 범위: 국내 상품, ETF, 국내·해외 공모펀드 등 4개 영역
- 외부 금융상품 데이터도 자유롭게 수집·활용 가능
- 다만 외부 데이터와 제공 데이터가 충돌하면 **주최 측 제공 데이터가 우선**
- ETF 구성 종목처럼 제공 데이터에 없는 정보는 기준일 이전의 외부 자료를 활용해야 함
- 기준일 이후 새로 생긴 상품이나 변경된 정보로 답하면 감점될 수 있음

### 5. 모델 및 구현 조건

- 최종 답변 생성과 메인 에이전트에는 **HyperCLOVA X 사용**
- 데이터 수집·전처리·정제·검색 등 나머지 과정은 다른 방법과 도구 사용 가능
- CLOVA Studio는 모델 테스트·튜닝·파라미터 조정을 위한 도구
- 실제 에이전트는 발급받은 API Key를 이용해 HyperCLOVA X API와 직접 통신
- 발표에서는 튜닝에 상대적으로 유리한 모델로 **HCX-005**를 권장
- 예선은 UI가 아니라 **API 성능**을 평가
- 본선에서는 UI와 라이브 데모가 경쟁력으로 작용할 수 있음

### 6. 네이버클라우드 환경

- 행사 크레딧: **20만 원**
- 신규 사용자는 웰컴 크레딧 약 **10만 원** 추가 신청 가능
- 크레딧 유효기간: **9월 30일**
- 기간이 지나도 서버나 상품을 삭제하지 않으면 실제 비용이 청구될 수 있음
- 계정 생성뿐 아니라 결제용 카드 등록과 쿠폰 등록까지 완료해야 함

권장 서버 구성:

- 2 vCPU / 메모리 4GB
- 저장공간 약 20GB
- VPC, 서브넷, 서버, 공인 IP 및 방화벽 설정 필요
- 외부 평가를 위해 HTTP/HTTPS 포트 개방 필요
- HTTPS 적용 시 도메인과 인증서가 필요할 수 있으며, IP 또는 별도 서브도메인 제공 여부는 추후 안내 예정

### 7. 평가 방식

총점은 100점입니다.

- 소스 코드: **20점**
- 기술 제안서: **40점**
- 평가 API의 호출 결과·답변: **40점**

API 평가는 다음과 같이 진행됩니다.

- 약 30문항: 상·중·하 각 10문항
- 모든 팀에 동일한 질문 사용
- 한 번에 하나씩 순차 호출
- 단일 질문–단일 답변 방식이며 멀티턴은 평가하지 않음
- 정답 문구의 일치보다는 필수 개체·관계·근거의 포함 여부를 평가
- 정확성뿐 아니라 응답시간도 평가
- 문항당 60초 이내가 권장이지만, 60초도 실질적으로는 느린 것으로 간주
- 별도의 답변 불가 질의 약 5개를 출제하며, 없는 정보를 생성하면 감점
